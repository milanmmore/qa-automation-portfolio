Git Workflow

Essential Git Commands & Best Practices for QA Automation

Why Git Matters in QA

Git is a critical skill for QA engineers and automation testers. It helps you manage test code, collaborate with developers, track changes, and maintain clean version control across automation frameworks, test data, and documentation.

1. Initial Setup

Set Git Username & Email

git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"

Check Configuration

git config --global --list

2. Creating or Cloning a Repository

Create a New Repo

git init

Clone an Existing Repo

git clone https://github.com/username/repository.git

3. Standard Git Workflow

Check Status

git status

Stage Changes

git add .

Commit Changes

git commit -m "Meaningful commit message"

Push to Remote

git push origin main

Pull Latest Changes

git pull origin main

4. Branching Strategy

Recommended QA branching model:

  • main – stable, production-ready code
  • dev – integration branch for new features
  • feature/xyz – individual work branches

Create a Branch

git checkout -b feature/my-new-test

Switch Branches

git checkout main

Merge a Branch

git merge feature/my-new-test

5. Handling Merge Conflicts

When Git detects conflicting changes:

  • Open the file in VS Code
  • Choose between Accept Current, Accept Incoming, or Manual Merge
  • Save the file
  • Stage and commit again
git add .
git commit -m "Resolved merge conflict"

6. Connecting to GitHub

Add Remote Origin

git remote add origin https://github.com/username/repository.git

Verify Remote

git remote -v

7. Commit Message Standards

Use clear, meaningful messages:

  • feat: new feature
  • fix: bug fix
  • test: test updates
  • docs: documentation changes
  • refactor: code cleanup
git commit -m "feat: added login test cases"

8. Git Workflow for QA Automation Projects

  1. Pull latest changes
  2. Create a feature branch
  3. Write tests / update framework
  4. Commit frequently
  5. Push branch to GitHub
  6. Create a Pull Request
  7. Get review → merge to dev → merge to main

9. GitHub Pages Deployment (Optional)

If your portfolio uses GitHub Pages:

git checkout -b gh-pages
git push origin gh-pages

Then enable GitHub Pages in repo settings.
